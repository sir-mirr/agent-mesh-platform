## 1. 📋 검수 1단계 개선 및 기획 재편 요약

검수 1단계에서 제시된 12개 검토 항목을 바탕으로 다음 4대 핵심 기획 방향을 확립하고 정보구조를 재편하였습니다.

### 1.1. 단일 로그인(Single Login) 및 단일 ID 기반 RBAC 역할 제어
- **로그인 단순화**: GitHub OAuth 또는 ID/PW(로컬 계정)의 **단일 로그인 진입점**으로 통합. (기업용 SAML/SSO 및 2FA 마스터 로그인은 상용화 페이즈로 이관)
- **단일 계정(Single ID)**: 테넌트 관리자, 그룹 관리자, 에이전트 운영자는 별도 계정이 아닌 하나의 계정으로 로그인한 뒤 부여된 **역할(Role) 및 역량(Capability)**에 따라 동적으로 메뉴 활성화.
- **메뉴 은닉 (Hidden by default)**: 테넌트 관리 권한이 없는 일반 에이전트 운영자에게는 **테넌트 관리 콘솔 메뉴 자체가 기본적으로 노출되지 않음**.

### 1.2. 플랫폼 스위트: 현재 가동 중인 실시간 서버 모니터링 집중
- 대규모 분산 환경의 인터게이트웨이 백본 하이웨이 및 페일오버 시뮬레이터는 상용화 페이즈로 이관.
- **현재 단일 허브 및 HTTP 서버의 실시간 헬스(`/health`, `online_agents`), 프로세스 텔레메트리, 테넌트별 메시지 라우팅 처리 건수(Routing Count) 및 스토리지 점유율 모니터링**에 집중.

### 1.3. 에이전트 운영 스튜디오(Studio): 스웜 그룹 관리 기능 신규 편입
- 에이전트 운영자가 실제로 스웜 그룹을 생성하고, 자신의 에이전트를 특정 그룹에 배속 및 이동(`POST /api/v1/admin/groups/{group_id}/members`)할 수 있도록 **[스웜 그룹 관리 & 에이전트 배속]** 메뉴를 운영 스튜디오의 핵심으로 편입.

### 1.4. 전체 기능 4대 페이즈(Phase 1 ~ Phase 4) 분리 및 미뤄둔 항목 체계화
- **Phase 1 (현재 집중 MVP)**: 단일 패브릭 필수 운영 및 에이전트 스튜디오 콘솔
- **Phase 2 (확장 거버넌스 & 개발자 허브)**: Root Ed25519 CA, 무중단 키 로테이션, 개발자 허브 및 3대 공식 SDK
- **Phase 3 (엔터프라이즈 컴플라이언스)**: 감사자 본문 열람 감사 로그 고도화, ASN 휴면 차단, 본문 물리적 분리/암호화
- **Phase 4 (상용화 페이즈 - Commercial)**: 14개 백본 하이웨이, 멀티 리전 페일오버, Redis 토큰 버킷 스로틀링, 기업용 SSO/2FA, SIEM 연동

## 2. 🚀 Phase 1 집중 계층형 정보구조도 (2줄 직관 박스)

```
┌──────────────────────────────────────────────────────────┐
│ [1행] 메뉴 (하위메뉴) 명                                 │
│ [2행] 핵심 기능 및 사용 목적에 대한 간결한 설명         │
└──────────────────────────────────────────────────────────┘
```
